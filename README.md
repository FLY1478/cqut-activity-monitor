## 运行

独立手动工作流 `Single-user cloud end-to-end test` 只用于本人授权的验证：正常沙箱下全新登录和完整采集、新进程恢复及完整采集、模拟采集会话丢失后的重新认证、向本人发送一条汇总。不报名、不配置定时器、不上传原始制品。自然过期续期、跨运行持久化和72小时观察仍需后续验收；微信接口接受与手机实际收到分开确认。

云端浏览器兼容性已在GitHub标准Ubuntu24.04原生运行器通过：项目实际启动器保留Chrome沙箱，模拟操作、重启模拟会话、提交拦截及学校匿名认证页访问成功。新增手动 `Anonymous browser compatibility` 工作流不使用Secrets或定时任务；Linux沙箱无法确认即停止。新增空列表保护和仅学校恢复模式后，本机类型检查通过，51项测试中50项通过、1项Linux专属检查按平台跳过。当前华为云函数的命名空间限制与替代方案见[ADR0004](docs/adr/0004-managed-browser-runner.md)，有凭据测试边界见[ADR0005](docs/adr/0005-credentialed-cloud-test.md)。

需要 Windows、Node.js ≥22.18 和已安装的 Chrome。首次配置学校账号使用本机凭据窗口，密码无需写入终端或聊天。

```powershell
npm ci
npm run check
npm test
$env:CQUT_PRIVATE_DIR = '<本机私有目录绝对路径>'
$env:CQUT_CHROMIUM_PATH = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File scripts/credentials.ps1 -OutputPath "$env:CQUT_PRIVATE_DIR/credentials.dpapi"
npm run local -- --no-send # 完整只读扫描
npm run local             # 扫描并发送待发提醒
npm run watch             # 北京时间08:00—20:00，目标每180分钟扫描；19:00每日汇总
npm run dashboard         # 本机管理页面，默认模拟报名
```

保持 dashboard 终端运行，在另一个终端执行 `npm run open`，通过加密保存的一次性入口打开浏览器。首次打开后使用同一浏览器会话；重启 dashboard 可生成新的入口。本机网页只绑定 127.0.0.1，手机不能直接访问这台电脑的回环地址。

凭据、会话、个人条件、页面原文、数据库状态和令牌使用 Windows DPAPI 当前用户加密整个对象。加密文件绑定当前电脑与 Windows 用户。不可提交到 Git 或复制到 Linux 后直接使用。微信配置入口为 `scripts/wechat-setup.ts`，只在本机验证阶段提供一次性回环配置接口。

## 监测与分析

- 使用学校手机网页的正常登录及原始活动详情链接。直接 HTTP 入口存在浏览器校验，当前采用正常 Chrome 和受支持的本机 CDP 接口。
- 当前活动列表返回完整数组，核对列表与页面稳定 ID；项目、课程入口检查完整分页。当前两者为空，若出现内容但尚未适配，扫描明确失败，避免静默漏报。
- 有效非空列表突然全部为空时，采集快照和监测基线均拒绝覆盖，保留上次结果并报告异常；不会生成“暂无活动”结论。首次运行的正常空列表仍可保存。真实活动全部结束的情况需要另外核实后再重建基线，不能靠反复出现空列表自动判定正常。
- 逐项读取详情，等待页面完成；空详情正常重载一次。详情与对应标题或明确 ID 不一致时不能算可靠读取。
- 明确学院、年级、校区不符时排除；资料不足、正文复杂限制或地点不明标为待核实。专升本不被自动等同为低年级，也不因“本科生”直接排除。
- 线上轻量任务及普通讲座优先；比赛、实际运动、实践、作品和长篇文字标明投入。偏好影响排序，不能替代学校资格规则或保证获得积分。
- 卡片以用户提供的 V11 为视觉基准：白色圆角单列、难度色条和彩色胶囊标签，点击展开详情和浅黄色点评。收起时保留名额、资格、截止、模块积分、任务标签和材料摘要；展开后补齐时间窗口、地点、方式及限制。微信采用同样配色的静态分区。定位、签退、总结等标签以可靠字段和正文证据为准，不承诺签到即可得分。
- 通知含模块、报名与活动窗口、地点、方式、人数上限、已报人数、是否已满、学院与年级限制、评价和材料要求。模板字符限额内分批，所有事件保留在加密队列，不静默丢弃其余活动。
- 2026-10-13最新时间安排：正常检查目标08:00、11:00、14:00、17:00，19:00额外汇总；晚间汇总失败可在20:00前每30分钟补试。每天最多约5次正常完整扫描，发现新活动可能延迟三小时。
- 每日19:00汇总一次；新增、开放报名、名额恢复和重要修改另行提醒，同轮合并成一条图文。普通人数波动不提醒。`--watch` 和单次 `--scheduled` 使用北京时间08:00—20:00窗口，20:00起不扫描、不主动发活动通知。每180分钟检查是目标，无法保证捕获两次检查之间出现又消失的名额。手动单次运行仍可用于显式测试。
- 汇总由19:00后的完整扫描生成，通常晚于19:00数分钟。故障恢复可在20:00前补当日汇总；次日不补昨日汇总。无可考虑活动也发一条状态。发送结果未知时保留记录，不自动重发。此时间策略已在本机代码实现，云端定时运行尚未启用。
- 先保存待发记录，再发送；接口接受与本人收到分开记录。超时、发送后崩溃保留未知状态，不自动无限重发。待发消息按最新明确条件复核，过滤和分批均保留原始记录。

## 报名测试边界

默认“一键报名 · 模拟”只调用模拟适配器，测试验证码为 1234。真实学校页面只读准备可显示真实验证码，浏览器层拦截学校报名及其他未知写入请求；**所有测试均未点击学校报名按钮，也未调用真实报名提交接口**。

真实提交适配器已编写，但没有实际报名成功验收。独立参数 `npm run dashboard -- --allow-live-signup` 才启用真实模式；本阶段未运行该参数。真实模式须本人手动填写数字验证码并明确确认，可能无法取消；不自动识别验证码、不背景报名、不自动重试。提交前重新读取实际详情，不依据旧扫描直接报名。

准备与提交有冷却，至少间隔 30 秒，10 分钟最多 3 次提交；意图三分钟过期，重复点击只执行一次。提交前持久化状态，结果未知或崩溃后要求先核实学校记录。扫描与报名准备共用执行锁。

## 微信与网页版

当前本机配置优先使用微信官方的单人图文预览：上传图文素材后，仅向已配置的本人发送预览，没有向全部关注者群发或公开发布。已实际确认微信内可直接打开排版卡片，无需先登录学校。模块、时间、地点、名额、资格、参加要求及提交材料均在卡片正文中；底部“阅读原文”才进入学校报名页，可能需要学校认证。卡片属于扫描快照，不代表实时名额。

使用 [上传图文素材](https://developers.weixin.qq.com/doc/service/api/notify/message/api_uploadnewsmsg.html) 和 [发送预览](https://developers.weixin.qq.com/doc/service/api/notify/message/api_preview.html) 两个官方接口。测试号管理页当次显示预览额度 50 次／日；程序保守限制为每天 40 次尝试（按北京时间计日，发送前加密保存预算）。明确被拒绝或达到预算时，退回已验证的文字模板；结果未知时不再发另一条。图文通知和文字模板均保存接受、失败或未知状态；接受不等同于收到。

微信模板接口不能渲染 HTML，其点击链接仍进入学校认证／详情页。交互管理页面及“一键报名”目前只在本机可用，手机上的独立私有管理网页仍需云部署；微信图文卡片本身已经可以在手机阅读。

官方图片客服消息另有主动交互额度和有效期，不能代替长期模板提醒。[官方规则](https://developers.weixin.qq.com/doc/service/api/customer/message/api_sendcustommessage.html)目前对用户发消息为 48 小时内 5 条；关注和扫码等场景窗口更短。图片实验返回 45015，未通过；当前测试号尚未配置消息回调 URL，二者关联尚未验证。不要把图片上传成功当作用户收到卡片。
