# ADR 0002：白天检查与19:00汇总

状态：本机调度已实现；云端手动主链路已通过，生产定时待验收。更新：2026-10-13。

用户将全天五分钟检查改为较低频白天检查、每日固定汇总加重要变化提醒；最终明确选择每天19:00，替代09:00。

采用北京时间08:00—20:00窗口，用户最新明确改为每180分钟检查，目标08:00、11:00、14:00、17:00；19:00额外完整扫描后汇总一条，失败间隔30分钟补试至20:00。变化按已有稳定ID和关键字段判断，同轮合并图文；汇总包含当前可考虑及待核实项目和具体名额、参加、材料字段。无活动也报成功状态，失败不伪装为空。日汇总ID及最近采集尝试时间持久化；超时结果不重发；失败重试限频；20:00起不启动采集或主动发送活动消息，次日不补昨日摘要。手动一次测试可显式运行。

备选：全天扫描（用量与用户需求不符）；只每日一次（可能错过较短报名窗口）；白天半小时检查（早期方案，已被三小时替代）；白天三小时检查加19:00汇总（当前采用，可能延迟发现短窗口活动）。较低频详情缓存尚未启用。

故障监测应按工作窗口的预期运行节点判断，原20分钟无心跳阈值不再适用。建议按计划时段连续漏两轮并预留采集时间；三小时间隔不能沿用此前75分钟阈值，普通扫描可暂按约6.5小时宽限设计，19:00汇总另按20:00前完成检查，夜间静默不报停机；尚未配置外部监测。

验证：最新类型检查及51项中50项本机测试通过，Linux专属存储检查按平台跳过；历史40项模拟测试通过，含时间边界、每日去重、空摘要、故障限频、采集提交后中断再恢复不重复发摘要与更新、十项活动合并单条图文。新增时间与卡片验证不连接学校或发送消息；此前云端29项真实汇总已由用户确认实收，见ADR0005。无真实报名；生产云端尚未部署。Apify无凭据测试历史诊断缺少沙箱／命名空间支持。
